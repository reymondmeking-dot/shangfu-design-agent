# 技术路线与产出物

## 九步业务流程

| 步骤 | 输入 | 技术与约束 | 输出 |
| --- | --- | --- | --- |
| 1 需求录入 | 场景、项目名称和客户原话 | FastAPI 和 SQLite 为项目和本次录入分别编号，原话单独入库 | 项目编号、需求录入编号 |
| 2 需求解构 | 客户原话 | Ollama 的 Qwen3 按 Pydantic 结构提取，服务回查引用是否出自原话。未指定项保留待确认状态 | 六维参数草稿、情绪审美标签、原话依据 |
| 3 人工确认 | 顾问校对的草稿 | FastAPI 验证用户原话字段的引用。顾问确认后的参数和来源单独留存。硬要求冲突进入追问 | 已确认需求版本 |
| 4 资源匹配 | 已确认需求、四类标签库 | SQLite 按类型、场景取数，Python 筛硬条件，再评估偏好和组合相容性。无合格结果可回到需求确认 | 资源编号、匹配依据、排除原因和可行性提示 |
| 5 方案初稿 | 需求版本、选定的版型、面料、工艺、案例 | 同版资产驱动款式与 Jinja2 文本，引用资产编号，保留未定事项 | 风格定位、面料推荐、版型、工艺、场景和设计亮点 |
| 6 技术图与提示词 | 当前款式模板、方案版本与尺寸参数 | 共享参数几何驱动 SVG 和 ezdxf。Jinja2 生成正背面、工艺特写、上身场景三种提示词。方案、图纸和视觉需求包关联同一版本 | SVG、DXF、三套提示词、视觉需求包 |
| 7 版师复核 | 方案、图纸、参数差异和意见 | 人工选择通过、退回设计或退回需求。请求校验目标图纸和版本；更新幂等与并发版本保护防止旧意见覆盖新版 | 复核事件、后续修改版本 |
| 8 归档导出 | 已复核的版本快照 | SQLite 留存反馈、确认人及图纸号。XlsxWriter 写入可编辑台账；ZIP 汇集方案和视觉文件。正式核对版交付包另检查三张写实图的复核状态 | XLSX 台账、工作包或经核对的交付包 |
| 9 复盘复用 | 已获准复用的检查项 | SQLite 关联原案例与新项目。人员确认后才带入下一单 | 下一单候选检查项及原项目出处 |

## 组件分工

浏览器请求进入 `src/worker.mjs`。本地由 `src/local.mjs` 适配 Node HTTP；部署也可使用 Worker。配置私有服务地址后，网关把项目写入请求转给 FastAPI。文本、图片和导出各自保留服务状态。

| 位置 | 实际分工 |
| --- | --- |
| `src/engine.mjs`、`src/demo-cases.mjs`、`src/knowledge.mjs` | 四类静态模拟资产、两套公开模拟需求、标签与参考资料索引 |
| `python_service/app.py`、`schema.py`、`db.py` | 状态流转、Pydantic 输入校验、SQLite 事务与项目事件 |
| `python_service/domain.py` 和 `domain_bridge.mjs` | 对接 Ollama，验证原句引文；Python 在 SQLite 资源中匹配，共享 JS 词表与款式规则 |
| `src/exports.mjs`、`python_service/render.py` 和 `templates/` | 可复算款式几何、Jinja2 方案模板、毫米制 DXF、SVG 技术平面图、可编辑 XLSX |
| `src/photos.mjs`、`visual-preview.mjs`、`python_service/visual_store.py` | 区分参数示意、已核对样图和实时生图，绑定项目、方案版本、图片摘要、复核意见 |

Node 单独启动也可运行浏览器存储演示。要验证 SQLite 归档和服务端版师复核，应使用根目录的双进程启动器。

## 图纸与视觉精度

DXF 以毫米记录轮廓、结构、工艺、尺寸、校尺和说明。查看 `CALIBRATION` 图层的 100 mm 校尺，可核对导入比例。版师可把 V1 门襟从 30 改到 35 mm，查看尺寸标记、图纸编号和复核事件的变化。基版衣长、肩宽、袖长均为模拟尺寸，实际量体、放码、缝份、样衣松量与生产版修订由版师负责。

| 视觉输出 | 目标尺寸 | 核对点 |
| --- | --- | --- |
| 成衣正背面 | 1500 × 1000 px | 正背是否同一件服装、同尺度，领型与下摆是否可见 |
| 工艺与材质特写 | 1200 × 1200 px | 工艺位置、袋口或门襟结构、织物表面 |
| 上身与场景 | 1200 × 1500 px | 人群、站姿与使用动作，肩、袖口和下摆是否清楚 |

可选 Workers AI 模型由 `src/photos.mjs` 指定。使用自己的 Wrangler 身份、Workers AI 与 Images 绑定，在本机设置 `SHANGFU_REMOTE_IMAGES=1` 后运行启动器，向该服务提交已选方案及当前视觉需求。成衣图用于约束细节图和上身图；每张结果分别留摘要和复核记录。无法生成时可导出提示词，交由设计人员在自己的图像工具中复核。图片像素只表示展示尺寸，规格与测量基准以技术图和实物复核为准。

## 工作台 HTTP 接口

浏览器接口路径均以 `/design-agent/api` 开头。公网演示免密开放，访客草稿保存在当前浏览器。内部 FastAPI 通过服务端令牌访问，浏览器不持有该令牌。公开运行示例的两个本地服务只绑定回环地址。

| 方法与路径 | 请求或响应 |
| --- | --- |
| `GET /health`、`GET /catalog`、`GET /catalog.csv` | 后端与模型状态、资源分类、模拟项目和分类 CSV |
| `POST /projects`、`GET /projects/{id}` | 建立项目，读取需求、方案、图纸、事件和归档快照 |
| `POST /extract` | 传 `projectId`、`scene`、`text`；返回六维字段、来源和解构来源状态 |
| `POST /match` | 传录入编号和已校对的 `requirements`；返回候选、排除原因及推荐组合 |
| `POST /solution` | 传已确认需求、选定资产、目标版本和可选门襟参数；返回方案、SVG、DXF、提示词 |
| `POST /projects/{id}/review`、`/archive`、`/reuse` | 按方案和图纸编号登记版师意见、复核归档、批准复用 |
| `POST /visual/previews`、`/visual/photos`、`/visual/photo` | 渲染三种参数示意、匹配已核对样图、由可选图像服务生成一张新图 |
| `POST /export/xlsx`、`/export/bundle`、`/export/delivery` | 导出可编辑台账、内部工作包、复核交付包 |

可执行的完整请求体见 `test/python-workflow.py`，从两次重复的录入请求到下一单复用均有相应断言。

## Agent 能力边界清单

- 资产检索、六维解构、组合推荐、技术图、提示词和台账用于洽谈辅助。硬要求缺少证据或候选不合格时，显式留待人工处理。
- 客户确认风格与使用约束。顾问记录修改意见。版师负责量体、试穿、适配和版型终审。商务人员负责报价、合同签订和生产下单。
- 公开演示只含虚构项目和静态模拟资产。专业参考资料提供测量和验证的方法，实际成分、色牢度、洗后尺寸、批次色差须取样核对。
- 画面表达目标款式和氛围。经人工复核的方案和写实图按版本关联。修改需求或尺寸后需要重新检查图像和技术图。

## 落地路径

1. 用两套模拟项目演练需求追问、资产选择、版师退回和复用，记录哪一处信息缺失直接影响后续设计。
2. 由资产负责人核验款式模板、样布编号、护理及工艺适配关系；由版师核验图层、测量起止点和特殊工艺。经允许的资产独立维护版本。
3. 在内部试点比较每单确认轮数、资源选择理由完整度、退回后图纸一致性及台账完整度，再决定推广范围。真实业务对接需另行授权并设计项目权限、保留期限和访问审计。

## 文件格式与命名

每份订单文件按 `项目名称_项目编号_V版次_文件用途.扩展名` 命名。例如 `酒店礼宾夹克_DEMO-SH-01_V2_业务台账.xlsx`。单独下载图片时，文件名也注明视图。整库下载固定使用 `定制资源分类清单.csv`。

| 内容 | 文件格式 | 核对方法 |
| --- | --- | --- |
| 定制资源分类、客户需求参数 | CSV（UTF-8，含 BOM） | 在表格软件中按逗号分列，核对资源编号与原话 |
| 情绪审美、方案初稿、适配与可行性、视觉提示词和视觉需求包 | Markdown（UTF-8） | 对照同版方案编号、资源编号与客户原话 |
| 业务台账 | 可编辑 XLSX | 按“项目汇总、需求与审美、方案与资源、视觉与图纸、操作与版本”的顺序查看 |
| 款式图 | SVG、DXF | DXF 使用毫米；导入后量取图中的 100 mm 校尺 |
| 成衣正背面、工艺与材质特写、上身图 | JPG 效果图、SVG 示意图 | 三种视图依次为 1500 × 1000、1200 × 1200、1200 × 1500 px |
| 内部工作包、核对版交付包 | ZIP | 按编号阅读，使用包内 JSON 清单核对项目、版次和图片 |

下载接口用 `Content-Disposition` 的 `filename*` 返回 UTF-8 文件名。`filename` 为兼容早期客户端的 ASCII 名称。

## 本机项目库

启动本机服务后，在工作台侧栏打开“本地项目库”。公开演示的草稿与本机 SQLite 分开保存。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /design-agent/api/health` | 查看数据库连接，SQLite 服务返回 `backend=fastapi`、`storage=sqlite` |
| `GET /design-agent/api/projects` | 列出本机项目编号及当前修订号 |
| `POST /design-agent/api/projects` | 用项目名称、定制类型和可选的客户原话 `rawText` 建立草稿 |
| `GET /design-agent/api/projects/{id}` | 读取指定项目、客户原话和版本记录 |
| `DELETE /design-agent/api/projects/{id}?expectedRevision=N` | 从项目库移除指定项目。修订号来自项目列表；若收到 409，重新读取后再确认删除 |
